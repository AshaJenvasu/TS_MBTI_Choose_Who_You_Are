# ADR-005: Test Scoring Methodology — Likert-weighted, 24 Questions

**Status:** ✅ Accepted (2026-11-24)

## Context
Ticket 2 (`POST /test/submit`) ใช้ scoring แบบ placeholder: 20 คำตอบ แบ่งเป็น 4 กลุ่มกลุ่มละ 5 ข้อ
นับผลรวมเทียบกับค่ากลางแล้วเลือกตัวอักษร (binary count) วิธีนี้หยาบเกินไป
และมี response bias แบบ "ตอบเห็นด้วยทุกข้อ" ที่ทำให้ผลเอียงไปทางตัวอักษรตัวแรกเสมอ
ต้องกำหนดวิธีให้คะแนนที่สมจริงขึ้นก่อนเริ่ม ticket ถัดไป (GET /results) โดยไม่เพิ่ม percentage breakdown ใน response

## Decision
- **Likert 5 ระดับถ่วงน้ำหนัก:** value 1-5 แปลงเป็น weight −2, −1, 0, +1, +2 (3 = กลาง) เพราะให้ผลละเอียดและสมจริงกว่า binary count
- **แต่ละ axis มี 6 ข้อ แบ่ง 4:2 ผสม pole ทั้ง 2 ทาง (reverse-scored):** 4 ข้อชี้ไปตัวอักษรหลัก (E/S/T/J) และ 2 ข้อชี้ไปตัวอักษรรอง (I/N/F/P) เรียงคงที่ตามตำแหน่ง [หลัก, รอง, หลัก, หลัก, รอง, หลัก] ข้อที่เห็นด้วยกับตัวอักษรหนึ่ง = ไม่เห็นด้วยกับอีกตัว การมีข้อ reverse-scored ทำให้คำตอบไม่ใช่แค่ "เห็นด้วยทุกข้อ" แล้วได้ผลเดิม และสัดส่วน 4:2 ทำให้ตอบค่าเดียวกันทุกข้อไม่เสมอกันอีก (ดูผลด้านล่าง)
- **รวม 24 ข้อ (6 ข้อ × 4 axis: EI, SN, TF, JP):** สมดุลระหว่างความแม่นยำกับ UX/completion rate
  tech lead สรุปจากการรีเสิร์ชคร่าวๆ ว่าจุดที่เหมาะสมของ personality quiz ทั่วไปอยู่ราว 13-24 ข้อ (ตัวเลขนี้มาจากการสรุปของ tech lead ไม่ได้ตรวจสอบซ้ำใน ticket นี้)
- **วิธีคำนวณ:** คำตอบแต่ละข้อบวก weight เข้ากับฝั่งที่ `pole` ของคำถามชี้ไป แล้วเทียบ 2 ฝั่งต่อ axis (ผลต่าง = คะแนนตัวอักษรแรก − คะแนนตัวอักษรที่สอง) มากกว่า 0 ได้ตัวแรก น้อยกว่า 0 ได้ตัวที่สอง
- **เสมอกันพอดี (ผลต่าง = 0) → default ไปตัวอักษรที่มาก่อนตามธรรมเนียม MBTI (E, S, T, J)** ต้องมีฝั่งหนึ่งชนะเสมอ และใช้ตัวที่ลิสต์ก่อนเป็นค่ามาตรฐาน ผลจึง deterministic และอธิบายง่าย
- **เก็บคำถามเป็น hardcoded constant (`services/question-bank.ts`) ไม่ใช่ DB table** เป็น static config ไม่ต้องทำ normalization เพิ่ม ข้อความคำถามเป็น placeholder จนกว่าจะถึง content stage
- **Request/response:** `answers` เป็น array 24 รายการพอดี `{ questionId, value }` (questionId ครบทุก id ไม่ซ้ำ ไม่ขาด ส่งลำดับไหนก็ได้) ผิดเงื่อนไขตอบ 400 `{ "error": { "code": "INVALID_ANSWERS", "message": "..." } }` สำเร็จตอบ 201 (สร้าง `test_result` แถวใหม่) response shape เดิม

## Consequences
- ✅ ผลลัพธ์ละเอียดกว่าเดิม
- ✅ การตอบค่าเดียวกันทุกข้อไม่เสมอกัน ต่อ axis: ตอบ 5 ทุกข้อ ผลต่าง = (+2×4) − (+2×2) = +4 ได้ E/S/T/J ส่วนตอบ 1 ทุกข้อ ผลต่าง = (−2×4) − (−2×2) = −4 ได้ I/N/F/P (ข้อชี้ตัวอักษรหลักมีน้ำหนักรวมมากกว่า แต่ตอนตอบ 1 น้ำหนักรวมนั้นติดลบ ตัวอักษรรองจึงชนะ)
- ✅ ตอบ 3 (เฉยๆ) ทุกข้อ ผลต่างเป็น 0 ทุก axis จึง fallback ไป ESTJ ตามกฎ tie นี่คือพฤติกรรมที่ตั้งใจ ไม่ใช่ข้อบกพร่อง
- ✅ ตรวจสอบง่าย: scoring เป็น pure function มี test ที่คำนวณมือไว้ล่วงหน้า
- ✅ ไม่ต้องมี migration หรือ endpoint เพิ่มสำหรับคำถาม
- ⚠️ เปลี่ยนคำถาม (เพิ่ม/ลบ/สลับ pole) ต้องแก้โค้ดและ deploy ใหม่ ไม่ใช่แก้ข้อมูล
- ⚠️ เปลี่ยน contract ของ `POST /test/submit` (shape ของ `answers`, error body, status 200) client ที่ใช้ shape เดิมต้องอัปเดตตาม
- ⚠️ ยังไม่มี percentage breakdown ใน response (แยกเป็น ticket เล็กถ้าต้องการ)
- ⚠️ จำนวนข้อ 24 ยังไม่ได้ตรวจสอบกับผู้ใช้จริง ปรับได้ภายหลัง

## Alternatives Considered
- **เก็บคำถามเป็น DB table + endpoint แยก** — ปัดตก เพราะ scope เกินจำเป็นสำหรับข้อมูลที่เป็น static config ที่เปลี่ยนไม่บ่อย
- **คง binary count เดิม** — ปัดตก เพราะหยาบและเอียงตาม response bias
- **สัดส่วน 3:3 ต่อ axis** — ปัดตก เพราะตอบค่าเดียวกันทุกข้อ (5 ทุกข้อหรือ 1 ทุกข้อ) หักล้างกันพอดีเป็นเสมอทั้ง 4 axis แล้วได้ ESTJ เสมอ แยกผลไม่ได้
- **จำนวนข้ออื่น (เช่น 13 หรือ 40+)** — ปัดตก 24 ข้อสมดุลที่สุดระหว่างความแม่นยำกับ completion rate ตามที่ tech lead สรุป

## หมายเหตุอัปเดต (2026-11-26)
- สถานะหลักฐาน: 24 ข้อ (6 ข้อ/แกน) และสัดส่วน 4:2 เป็นการตัดสินใจเชิงออกแบบ ไม่ได้อ้างอิงงานวิจัย
  ประโยคเดิมที่ว่า "13–24 ข้อ", "24 ข้อสมดุลที่สุด" และ "สมจริงกว่า binary count" เป็นการประเมินของผู้ออกแบบ ไม่มีแหล่งอ้างอิง
- ผลของ 4:2 ตามโค้ดจริง: ทำให้ตอบสูงสุดทุกข้อ (→ ESTJ, 67%) กับต่ำสุดทุกข้อ (→ INFP, 33%) แยกผลกันได้
  แต่ไม่ได้ขจัด acquiescence bias เพราะฝั่งตัวหลักมี 4 ข้อ ฝั่งตัวรอง 2 ข้อ ตอบ 5 ทุกข้อจึงยังเอียงไปตัวอักษรแรก (net +4 ต่อแกน)
  ตอบ 3 ทุกข้อ = เสมอ → ได้ตัวอักษรแรก
  ข้อความเดิมที่เขียนเหมือน 4:2 แก้ bias นี้ได้ทั้งหมดให้ถือตามหมายเหตุนี้
- ยอมรับเป็นข้อแลกเปลี่ยน เพราะเป็นแบบทดสอบเพื่อความบันเทิง ถ้าต้องการลด bias จริงต้องเปลี่ยนเป็น 3:3 และออกแบบ tie-break ใหม่ (ยังไม่ทำ)
- ข้อความเดิมที่ระบุว่ายังไม่มี percentage breakdown ล้าสมัยแล้ว (เพิ่มใน Ticket 5)
- แบบทดสอบนี้ไม่ได้ผ่านการ validate ทางจิตวิทยา
